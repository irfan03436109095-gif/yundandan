Mac 换成网线后代理失效？按网络服务检查设置

淡定点2026-10-07— 次阅读
客户端排障手册

Mac 在 Wi-Fi 下可以使用代理，插入网线后同一个浏览器却连不上，先确认检查的是当前网络服务。不能因为 Wi-Fi 的代理栏正确，就假定以太网服务采用相同设置。

本文适合使用 macOS 系统代理的读者。若应用自己配置代理，或客户端采用 TUN/VPN 接管，还需要按对应方式核对，不能只靠系统代理页面判断全部应用。

示意图：同一台 Mac 的不同网络服务，需要分别检查对应代理设置。

网络服务与节点是两个概念

Apple 官方说明把网络服务解释为特定网络端口或接口的一组设置，例如以太网或 Wi-Fi。代理设置入口也要求先选择一个网络服务，再进入“详细信息 → 代理”。

因此，这次排障要分别问：电脑正从哪一个接口联网，以及当前服务使用什么代理配置。机场节点没变，不意味着接口相关设置也自动一致。

先记录，再逐项核对

  1. 确认当前连接。 打开“系统设置 → 网络”，记录 Wi-Fi 与以太网的连接状态。两者都连着时，单凭插入网线不能断言请求一定从网线出去；先在适合操作的环境中确认使用路径。
  2. 进入对应服务。 选择正在检查的网络服务，打开“详细信息 → 代理”。不要仍停留在 Wi-Fi 页面修改以太网问题。
  3. 核对代理类型。 区分 HTTP、HTTPS、SOCKS、自动发现与 PAC。按客户端正式说明检查启用项，不把一个端口随意复制到所有类型。
  4. 核对本地入口。 在客户端查看实际监听地址和端口，再与当前服务填写值比较。示例中的常见端口不是你的实测端口。
  5. 保留例外条件。 私下记录绕过主机和域名、简单主机名例外及单位要求。需要改动时只处理已确认的一项，不整页清空。

受单位管理的 Mac 应先核对管理要求；不要为了个人排障删除网络服务、移除描述文件或重排组织配置。

用同一任务完成切网对照

记录原 Wi-Fi 条件下能够完成的一项任务，再在以太网条件下复现。保持客户端、节点和浏览器相同，观察目标页面、错误提示以及客户端能否看到相应连接。

如果浏览器成功而其他应用仍失败，继续核对该应用是否读取系统代理。反过来，系统代理栏一致而任务仍失败，也不能直接判断节点故障，还应检查网络连通与应用自己的设置。

怎样算恢复完成

你应能指出请求采用的网络服务，确认代理入口与客户端一致，并在预期切网条件下重复完成原任务。若本次临时改动影响其他网络服务，应按事前记录恢复并再检查本地或单位访问。机场推荐的上手验收，需要覆盖你实际使用的接口，而不只验一次 Wi-Fi。
